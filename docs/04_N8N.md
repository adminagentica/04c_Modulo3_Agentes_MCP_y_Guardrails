# Workflows n8n

Los archivos `demo/n8n/workflow.json` y `demo/n8n/consulta-gmail.json` son plantillas sin credenciales y desactivadas. Conservan los IDs de la demo para que sus enlaces coincidan. **Importarlos sobre una instancia que ya contiene esos IDs puede reemplazar un workflow:** hacer una copia de seguridad y revisar antes. No es necesario reimportar en el equipo del docente si ya funciona.

## Credenciales que se crean en n8n

| Tipo | Dónde se asigna | Configuración |
|---|---|---|
| Header Auth | Webhook de la app y nodos HTTP hacia Python | Nombre Authorization, valor Bearer seguido del token local |
| OpenAI API | OpenAI · Orquestador | API key de la cuenta destinada a clase |
| Gmail OAuth2 | Gmail Trigger y Gmail Send | Cliente OAuth de Google Cloud con Gmail API habilitada |

El token local está en `demo/data/gateway.token`. Copiarlo manualmente en la credencial local; no pegarlo en el chat ni subirlo al repositorio. Asignar la misma credencial Header Auth a todos los nodos que usen `httpHeaderAuth`. Los secretos quedan en el almacén cifrado de n8n.

## Recorrido de la app

Importar workflow.json, seleccionar las credenciales y publicar. Webhook: `POST http://127.0.0.1:5678/webhook/agentica-cobranza-chat`. El modo de prueba `/webhook-test/` no es la URL usada por la app. El nodo OpenAI recibe un payload creado por Python y llama Responses API. El backend comprueba contrato, citas y huella del caso antes de responder.

El modelo predeterminado está en `demo/src/web_orchestration.py` y es gpt-5.4-mini, con máximo una llamada por consulta, store=false, salida de hasta 1800 tokens y sin reintentos. Modificar el modelo exige revisar contrato, acceso y Evals. No poner la API key en expresiones ni en la app.

La rama manual contiene el multiagente didáctico anterior. No ejecutar todos sus nodos para comprobar la conexión: puede invocar modelos. La rama del webhook es la usada por app/Codex/Claude.

## Recorrido Gmail

Importar consulta-gmail.json, seleccionar Gmail OAuth2 y Header Auth y revisar el filtro antes de publicarlo. El trigger revisa cada minuto mensajes del asunto específico de prueba. Solo activar cuando se quiera responder de verdad a esa consulta sintética. Ver docs/07_CORREO.md.

## Comprobación sin consumir saldo

Primero ejecutar scripts/verificar.py. Para demostrar la conexión real publicada, el caso de DNI discordante de docs/03_GUION_CLASE.md termina antes de OpenAI. Inspeccionar que la ejecución solo haya pasado por Webhook, Contexto, IF y Aclaración. No ejecutar una pregunta válida como test gratuito.

Si falla después de reservar un correo, revisar Gmail antes de intervenir. No reiniciar o borrar el estado para forzar otro envío. Los JSON de distribución no incluyen pinData, memoria ni IDs de credenciales del docente.
